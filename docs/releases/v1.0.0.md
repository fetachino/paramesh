# ParamMesh v1.0.0 release candidate

This is a **candidate**, not a published release. The package version is
prepared as `1.0.0`; no `v1.0.0` tag, GitHub release or new GHCR image exists
from this branch. The current production image has OCI source revision
`2b1fbae42a5ea15cfa3507baed5f25a2533af33c` and predates PR #39. A final
release image must identify the eventual merged release commit, not that older
production digest or this branch's pre-merge SHA.

## Included behavior and evidence

- Fixed-topology parameter-server training with independent coordinator,
  shards and CPU workers in synchronous, asynchronous and bounded-staleness
  modes; the bundled workload is a seeded float32 PyTorch MLP.
- Durable receipts, worker journals, generation fencing, process restart and
  coordinated whole-run checkpoints. Local, authenticated SeaweedFS S3 and
  Azure Blob SDK against Azurite have restore/resume evidence.
- Private operations stack and an authenticated HTTPS operator dashboard.
- Real two-host x86-64 high-rate checkpoint correctness/recovery evidence and
  a separate single-host production [live rollback/restoration](../evidence/gcp-live-rollback-2026-11-04/README.md).
- PR #39's Windows checkpoint barrier recovery fix is included in source;
  [its regression evidence](../evidence/checkpoint-barrier-windows-2026-11-04/README.md)
  includes 10/10 repeated Windows trials. It is not in the older production image.

## Installation from a source checkout

Use Python 3.12 on Windows AMD64 or Linux x86-64. The lock also resolves Linux
ARM64 and an ARM64 Compose stack passed local emulation; native ARM64 hardware
has not been verified. The proposed GHCR release workflow publishes
**linux/amd64 only**.

```powershell
git clone https://github.com/fetachino/paramesh.git
cd paramesh
python -m pip install uv==0.13.6
uv sync --locked --all-extras --python 3.12
uv run paramesh --version
uv run paramesh demo --mode sync --workers 2 --shards 2 --steps 20 --output artifacts/sync.json
```

For the local operations profile, first run
`uv run python scripts/create_dev_env.py --operations`, then
`docker compose --profile operations up --build -d`. This generates a private,
ignored `.env` for that clone. Dashboard and Grafana usernames are `operator`;
their distinct passwords are in that local `.env`. Existing values are preserved
when the generator is rerun. See the [README](../../README.md),
[operations guide](../operations.md) and [checkpoint guide](../checkpoints.md).

## Known limits

- The model, optimizer and float32 CPU workload are fixed. Arbitrary user
  models, GPU training, per-tenant identity and Byzantine workers are outside
  this release.
- Live state is local to each role. A single host is not highly available;
  whole-run checkpoint restore requires the original topology and coordinated
  state, not selective shard rollback.
- Azure/Azurite tests establish Azure-compatible local behavior, not managed
  Azure durability. Native ARM64 and real multi-host scaling performance remain
  unverified. The two-host result is checkpoint correctness evidence.
- Compression is deferred because the measured workloads do not establish a
  bandwidth bottleneck. Do not infer an unmeasured throughput or latency target.
- The hosted VM consumes Google Cloud Free Trial credit. Public HTTPS covers
  only the operator dashboard; backend and Grafana endpoints remain private.
- Coolify's generated Compose currently retains application build stanzas.
  Follow the [immutable redeployment procedure](../immutable-deployment.md);
  an ordinary unreviewed Coolify redeploy is not a verified immutable rollout.
- A standalone demo in local QEMU ARM64 emulation hit its child-process startup
  deadline before training. The ARM64 Compose profile completed a separate
  10-step, two-worker run; native ARM64 timing remains unknown.
- Package advisory scans are point-in-time checks. They do not certify the
  container OS or eliminate the need to protect credentials and backups.

## Candidate checks

The locked Windows suite passed 142 tests with 91.62% coverage. Linux x86-64
Compose training, checkpoints, operations and local multi-host simulation
passed; the ARM64 Compose run above passed under QEMU. Ruff, mypy, generated
protocol, JavaScript syntax, lock freshness, wheel/source builds, an isolated
wheel install and a current OSV advisory scan passed. The
[release-readiness audit](../release-readiness.md) records the first local
Compose timeout caused by this PC's ignored 2,000-step paced `.env`, and its
process-only 20-step rerun with unchanged test assertions. GitHub Actions
exact-head validation for this PR remains a separate merge gate.

## Final image publication and provenance gate

After this PR merges and exact-head CI passes, record the **merged main SHA**.
Dispatch the [immutable image workflow](../../.github/workflows/immutable-image.yml)
with that exact 40-character `source_ref`. The workflow uses `GITHUB_TOKEN`
with `packages: write`, checks out the requested SHA, and derives the tag, OCI
revision, build date and release manifest from the resolved checkout. No
personal access token is required.

Before a tag or GitHub release, independently verify the workflow run and
artifact, the published registry digest, `linux/amd64` platform, OCI revision,
source SHA, package version, pinned base image, lockfile, and an exact-digest
registry pull. Run an isolated digest-qualified Compose smoke test and compare
its image identity and retained-state behavior with the manifest. Record the
immutable digest and any new limitations in the final release notes. The
published digest cannot be known before the registry build completes.

Run publication from a clean checkout of the merged release commit. Keep the
successful workflow run ID and its `immutable-release-$sourceSha` artifact with
the release evidence:

```powershell
$sourceSha = (git rev-parse origin/main).Trim()
gh workflow run immutable-image.yml --ref main -f "source_ref=$sourceSha"
# Select the successful run ID for this source SHA from the workflow run list.
gh run list --workflow immutable-image.yml --event workflow_dispatch --limit 10
$runId = 'REPLACE_WITH_SUCCESSFUL_RUN_ID'
gh run download $runId -n "immutable-release-$sourceSha" -D artifacts
$image = (Get-Content artifacts/immutable-release.json | ConvertFrom-Json).image
docker buildx imagetools inspect $image
docker pull $image
uv run python scripts/immutable_release.py verify --manifest artifacts/immutable-release.json --image $image
docker image inspect $image --format '{{ index .Config.Labels "org.opencontainers.image.revision" }}'
```

Compare the manifest's source SHA and digest with the successful workflow run,
registry manifest and OCI revision; require the source to equal the merged SHA
and the digest to equal the registry pull. Verify the isolated Compose
deployment uses the same digest and retains checkpoint state. Any mismatch
blocks the tag.

The Dockerfile now pins its Python and uv base images; `uv.lock` pins Python
packages. Build identity is traceable to source and inputs, but bit-for-bit
reproducibility across Docker/build-tool implementations is not claimed.
No production deployment is part of this release-candidate PR.
