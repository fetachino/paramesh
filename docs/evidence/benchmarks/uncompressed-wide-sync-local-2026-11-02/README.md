# Larger-payload synchronous loopback trial

Three real runs captured from clean source `e08be5be8ec64d873093515179641fe54d78787d`
on November 2, 2026 UTC. This extends the tiny-model baseline with wider parameters;
it does not emulate network delay or multiple hosts.

Host: Windows 11 AMD64, Intel Core i7-13700F, 24 logical CPUs, 34,055,766,016 bytes
OS-reported memory. Python 3.12.10 and PyTorch 2.15.0+cpu; exact lock hash, host
clock and trial metadata are in `manifest.json`. The retained Docker operations
stack remained running. Background workstation load was not controlled.

Configuration: synchronous SGD, two workers/two shards, 5 warm-up and 50 measured
steps per worker, 32 examples per worker, MLP 4-256-1, learning rate 0.05, float32
uncompressed transport and durable SQLite commits. Each worker sends 6,148 raw
gradient tensor bytes per iteration across the two shards, 31.4 times the 196-byte
gradient in the tiny baseline. Model compute also increases with width; throughput
is not an isolated transport result.

| Observation | Trial 1 | Trial 2 | Trial 3 | Median |
| --- | ---: | ---: | ---: | ---: |
| Processed examples/s | 4,007 | 4,196 | 2,399 | 4,007 |
| Successful push p95, ms | 5.119 | 3.284 | 8.970 | 5.119 |
| Successful pull p95, ms | 1.707 | 1.164 | 3.966 | 1.707 |
| Final full-dataset MSE | 0.08880 | 0.08880 | 0.08880 | 0.08880 |
| Max error vs equivalent local SGD | 1.19e-7 | 1.19e-7 | 1.19e-7 | 1.19e-7 |

All three trials completed 50 commits per shard, recorded zero failed RPCs, and
passed the existing `1e-6` numerical-reference gate. The observed throughput range
is large enough to show that three local repetitions are noisy. This dataset does
not establish a bandwidth bottleneck, compression benefit, multi-host scaling or
cloud-host performance. Compression remains deferred until controlled network
measurements justify it.

`trial-*.json` are unmodified raw trial records; `rpc.csv` records each captured
client attempt and protobuf sizes; `trials.csv` contains per-trial summaries. The
PNG/SVG charts are generated by the harness from those trial values. `SHA256SUMS`
covers every captured file except itself.
