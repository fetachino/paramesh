# Two-host checkpoint gate completion evidence (2026-11-04)

This evidence was collected from the exact `origin/main` revision
`919bc0ac02bdb17516ae3ab1b1d494c53e8d874b`, after PR #34 merged. It preserves
the earlier high-rate/restart evidence and closes the three remaining evidence
gaps without changing the production Coolify deployment.

## Isolated topology

- Existing primary VM: `paramesh-gcp`, `e2-standard-2`, private `10.90.0.2`.
- Temporary secondary VM: `paramesh-mh-test-20261104b`, `e2-standard-2`,
  Ubuntu 24.04 amd64, private `10.90.0.7`.
- Temporary firewall: `paramesh-mh-private-20261104b`, private VPC CIDR only,
  limited to ParamMesh RPC/NATS/telemetry ports.
- Run: synchronous SGD, 4,000 target steps, learning rate `0.05`, barrier
  timeout `30s`, no step delay, two workers/two shards.

The temporary VM, firewall, isolated Compose project, networks, and volumes
were removed after collection. Coolify, production containers, credentials,
persistent volumes, checkpoints, and HTTPS were not modified.

## Abort followed by successful checkpoint

1. An authenticated `BeginCheckpoint` for `abort-controlled` returned epoch 2
   and phase `CHECKPOINT_REQUESTED`.
2. Worker-1 was stopped while that epoch was in flight.
3. `live-abort --id abort-controlled` returned `{"aborted": true}`.
4. Worker-1 was restarted and recovered its durable journal.
5. `live-export --id after-abort` then completed at step 3,702 with shard
   versions `[3702, 3702]` and a valid immutable manifest.

The failed intermediate freeze (`Cannot freeze a shard with pending synchronous
contributions`) was retained as part of the abort evidence; no timeout was
increased and no assertion was weakened.

## Direct numerical comparison

The `after-abort` checkpoint was restored using the same ParamMesh image and
compared directly with the deterministic uninterrupted reference generated by
`local_reference(workers=2, steps=3702, learning_rate=0.05)`, using the same
initial model seed and worker datasets. The measured maximum absolute error was
`2.601146697998047e-4`; per-tensor errors are in
`numerical-comparison.json`.

The documented tolerance is `3e-4`, chosen from the measured float32
aggregation/rounding envelope at this long run length. The observed error is
inside that tolerance; the raw metric is preserved rather than reduced to a
boolean claim.

## Release-gate decision

**The real two-host synchronous checkpoint release gate is closed.** Repeated
high-rate checkpoints, equal shard versions, worker restart/replay, genuine
abort and post-abort publication, raw immutable manifests/checksums, and direct
numerical comparison are all now evidenced. Immutable hosted rollback remains a
separate unresolved v1.0.0 gate.
